# VYNL Authorization Specification (`docs/AUTHZ.md`)

This document defines the authorization model and access control matrix enforced inside the service domain layer.

---

## 1. Principles of Authorization

1. **Service-Layer Enforcement**: Authorization checks are performed by domain services (`PlaylistService`, `WrapService`) using trusted `Actor(user_id, is_internal, ...)` context objects. Transport handlers only extract session state and never make authorization decisions.
2. **Hidden Existence Principle**: Unauthenticated users or users with zero relationship to a private resource receive `404 Not Found` rather than `403 Forbidden` to prevent resource enumeration.
3. **Role Re-validation on Mutating Operations**: For WebSocket and streaming connections, membership and permissions are validated against the database on every mutating frame, not merely at handshake.

## 2. Playlist Service Authorization Matrix

| Action | Route | Owner | Editor | Viewer | Stranger |
|---|---|---|---|---|---|
| View playlist metadata & items | `GET /v1/playlists/{id}` | ✔ 200 | ✔ 200 | ✔ 200 | **404** |
| Get playback source & playable items | `GET /v1/playlists/{id}/playback` | ✔ 200 | ✔ 200 | ✔ 200 | **404** |
| Add item to playlist | `POST /v1/playlists/{id}/items` | ✔ 201 | ✔ 201 | **403** | **404** |
| Remove item from playlist | `DELETE /v1/playlists/{id}/items/{itemId}` | ✔ 200 | ✔ 200 | **403** | **404** |
| Reorder items (single or bulk diff) | `PATCH /v1/playlists/{id}/items/{itemId}` | ✔ 200 | ✔ 200 | **403** | **404** |
| Edit title, description, privacy | `PATCH /v1/playlists/{id}` | ✔ 200 | **403** | **403** | **404** |
| Delete entire playlist | `DELETE /v1/playlists/{id}` | ✔ 200 | **403** | **403** | **404** |
| Create collaborator invite link | `POST /v1/playlists/{id}/invites` | ✔ 201 | **403** | **403** | **404** |
| Revoke invite link | `DELETE /v1/playlists/{id}/invites/{inviteId}` | ✔ 200 | **403** | **403** | **404** |

## 4. Internal Route Authorization

Internal routes require `X-Internal-Auth` HMAC-SHA256 authentication:
- `DELETE /users/{id}/data`: Deletes PII across schemas (orchestrated by Account Deletion worker).
- `PUT /internal/drafts/{id}`: Saves draft generated by LLM worker.
- `GET /internal/playlists/{id}/context`: Extracts capped playlist context (≤50 items) for recommendation engine.
Calls without valid HMAC return `401 Unauthorized`.
